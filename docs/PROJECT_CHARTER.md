# tsolluos Project Charter

## Purpose

tsolluos is Michael's personal, non-commercial creative and technical project rooted in his ongoing study and practice of Sanatana Dharma, especially Advaita Vedanta, Sanskrit, the Bhagavad Gita, the Upanishads, meditation, and lessons learned through AA and lived experience.

The project is primarily being built for Michael himself as a personal breadcrumb trail, daily reminder, and record of learning.

Finished work may be shared freely and anonymously if it proves useful to others, but public reach is not the measure of the project's success.

## Guiding Question

Every concept, graphic, animation, interaction, and technical decision should return to one question:

> **What is the simplest truthful way to show this concept or lesson?**

Simplicity should reduce unnecessary complexity without sacrificing truthfulness or meaning.

## Role of the Project

tsolluos is a learning and exploration tool.

It may use software, graphics, animation, sound, rhythm, interaction, humor, and other creative techniques to make ideas easier to encounter, remember, explore, and revisit.

The project should create pointers toward deeper understanding rather than attempt to contain that understanding itself.

> **tsolluos isn't a destination. It's a doorway.**

## Relationship to Traditional Sources

tsolluos must learn from and point toward qualified teachers and trustworthy sources.

The project must not present Michael, the software, its graphics, or its interpretations as authorities on Sanatana Dharma or related traditions.

When educational or reflective material is included, the project should distinguish clearly between:

1. scripture or primary traditional sources
2. established commentary
3. teachings attributed to a named teacher
4. general interpretation or explanation
5. Michael's personal reflection or experience

Original sources should remain the primary references whenever possible.

A visual explanation, animation, summary, or interpretation should never quietly replace the source from which it was derived.

## Creative Principles

The project should favor:

* strong, memorable visuals
* animation when movement improves understanding
* minimal text when an image can communicate more clearly
* rhythm and sound when they serve the concept
* respectful humor
* discovery before explanation
* wonder before explanation
* gradual understanding
* simple interactions
* accessibility to beginners
* designs that remain understandable after long periods away from the project

Complex ideas should be reduced to their clearest useful form without being distorted merely to make them easier.

A useful secondary question is:

> **Could a child understand what this is trying to show?**

That question tests clarity, not intellectual depth.

## Technical Principles

The software should support the same philosophy as the content.

tsolluos should:

* prefer standards over unnecessary frameworks
* favor simple technology when simple technology is sufficient
* build the smallest version that works
* make source code readable and educational
* use useful comments so code can become part of the learning process
* keep files and components focused on one primary responsibility
* preserve a clear separation between experimentation and production
* use small, meaningful Git commits as chapters in the project's history
* treat documentation as part of the product
* remain maintainable after months or years away from the code

Technology should reduce friction rather than become the subject of the experience unless learning the technology is itself the current goal.

## Audience

The primary audience is Michael.

The project should therefore remain useful even if nobody else ever discovers it.

When material is suitable for sharing, it should also remain approachable to:

* complete beginners
* students
* curious children and adults
* people returning to a subject after months or years away
* sincere learners looking for a simple doorway toward trustworthy sources

No prior knowledge of graphics programming or the project's internal technology should be assumed.

## What tsolluos Is Not

tsolluos is not intended to:

* recreate or replace scripture
* replace qualified teachers
* present Michael as a spiritual authority
* present software as a spiritual authority
* preach or manipulate
* promote a personal brand
* turn personal interpretation into traditional teaching
* become another generic meditation application
* hide complexity behind unnecessary technical machinery

## Measure of Success

The project succeeds when it helps preserve learning, encourages sincere exploration, reduces friction, creates memorable connections, and makes it easier to return to trustworthy sources and practices.

It does not require an audience, followers, commercial success, or recognition to justify its existence.

If tsolluos remains useful as Michael's own breadcrumb trail, it has already fulfilled its primary purpose.

---

**Learn faithfully. Build simply. Point toward the source.**
